# v9.1 — 5형식 = 인식 스킬 (Recognition, not Mandate) — Design

> v9 축 진화. 세션이 모든 입력을 5형식으로 **강제**하던 것을, "이게 5형식 모먼트인가?"를 **판정**하고 — 맞으면 5형식으로 끌어올리며 *단서*를 가르치고, 아니면 간결형을 인정하며 *왜 과한지/단서*를 가르치도록 바꾼다.

## 1. 문제 / 목표

기존 v9: "모든 세션은 7패턴 중 정확히 하나를 표적." → 자연 영어가 3형식인 입력에도 5형식을 욱여넣어 **학습자의 '언제 어떤 구조를 쓰는가' 판단력을 해칠 수 있다.** 한국인의 진짜 결손은 "**5형식이 더 나은 *상황 자체*를 인식하지 못함**". 따라서 목표 = 강제가 아니라 **인식**: 5형식이 업그레이드면 그 단서와 함께 가르치고, 아니면 간결형이 정답임을 인정하고 과적용을 경계.

## 2. 결정 (사용자 확정)

- **접근 = A2 인식판정 단일 플로우.** 플로우 하나가 항상 "최선의 영어"(5형식 or 간결형)를 만들고, **인식 판정**이 1급 필드.
- **간결형 세션 SRS = 카드 미생성**(드릴할 5형식 없음), 단 **LearningRecord는 기록**(streak/기록 포함).
- **콘텐츠 팩(15개)은 별도 후속** — v9.1 머지 후 재작성(`feat/content-pack` WIP 보관됨).

## 3. 스키마 변경

### 3.1 `types/v9.ts` — `SessionPayload`
```ts
recognition: {                       // NEW — 교육 중심
  isFiveHMoment: boolean             // 판정: 5형식이 이 상황을 업그레이드하나?
  cue: string                        // 왜 — 인식 단서 ("목적어의 결과/상태까지 말할 때 → 5형식")
}
pattern5h: Pattern5HMeta | null      // 간결형이면 null
structure.comparison: {              // RESHAPED — 방향 무관
  show: boolean
  label: string
  fiveH: { en: string; note: string }      // 5형식 렌더 + 코멘트(자연 or 과함)
  simpler: { en: string; note: string }    // 간결형 렌더 + 코멘트
  betterChoice: '5h' | 'simpler'           // 이 입력에서 이긴 쪽 (= isFiveHMoment와 일관)
}
assembly.blocks: Block[]             // 2..3 (간결형은 2덩어리 가능; 기존 정확히 3 완화)
assembly.blockRoles: BlockRole[]     // length === blocks.length
pattern: PatternTemplate | null      // 간결형이면 null (저장할 5형식 카드 없음)
```
- `patternQuiz`는 **스키마 그대로**, 의미만 이중: 모먼트=동사 인식 / 비모먼트="여기 5형식 필요?" 형식 인식(옵션 text가 동사 대신 "5형식으로"/"간결하게"). 3옵션+`unsure`+정답1 규칙 동일.
- `Block.id`: 2블록이면 `b1`/`b2`. `Block.order` 1..N.

### 3.2 `types/index.ts` — `LearningRecord` (schema v6)
```ts
schemaVersion: 4 | 5 | 6             // 신규 기록 = 6
pattern5hId: Pattern5HId | null      // 간결형이면 null
triggerVerb: string | null           // 간결형이면 null
isFiveHMoment: boolean               // NEW — 인식 결과 기록(분석/Review 칩)
```
- **v5→v6 비파괴:** 기존 v5 기록은 전부 5형식(pattern5hId 비어있지 않음)이므로 의미상 `isFiveHMoment=true`. 읽기 시 누락이면 true로 간주(localStorage 마이그레이션에서 백필 or 읽기 기본값). 기존 데이터 무손실.

## 4. 검증 `validate.ts` (판별형)
- `recognition` 필수: `isFiveHMoment` boolean, `cue` 비어있지 않은 string.
- `comparison.betterChoice` ∈ {'5h','simpler'} 이고 `isFiveHMoment`와 일관(true↔'5h').
- `comparison.fiveH.en` / `simpler.en` 비어있지 않음.
- **isFiveHMoment === true:** `pattern5h` 필수(+ 큐레이션 동사 검증, `verbs` non-empty), `pattern` 필수(`patternId === pattern5h.id`, template/tags).
- **isFiveHMoment === false:** `pattern5h === null`, `pattern === null`.
- `assembly.blocks` 길이 2..3, id 유일, order 1..N 연속; `blockRoles.length === blocks.length`, 유효 role.
- `patternQuiz` 3옵션+unsure+비-unsure 정답1 (기존). triggerVerb 큐레이션 검증은 pattern5h 있을 때만.
- precheck/structure.parts/feedback.wordOrder/patternNote — 기존 그대로.

## 5. 플로우 (7스텝 단일, 조건 분기)
- **step0 `StepStructure`:** 상단에 **인식 판정 배너**(모먼트 ✓ / 간결형 ✓ + `cue`). `Pattern5HChip`은 pattern5h 있을 때만. `ComparisonCard` 새 형태(양쪽 렌더 + `betterChoice` 강조). `patternQuiz`(동사 or 형식 인식).
- **step1 `StepAssemble`:** `betterChoice` 문장 조립. 블록 2~3 지원.
- **step2 `StepFeedback`:** 정답 판정 + wordOrder + `patternNote`(비모먼트="여기선 간결형이 자연, 5형식은 과함"). 버튼: 모먼트="이 패턴 내 걸로 만들기" / 비모먼트="확인"(저장 없음).
- **step3 `StepReflect`:** 모먼트일 때만 패턴 저장 + verb family. 비모먼트=인식 takeaway("이런 단서면 간결형 — 5형식 아껴").
- **step4 `StepComplete`:** 동일.

## 6. 스토어 `learningStore.ts`
- `isAssemblyCorrect`: 하드코딩 `blockOrder.length !== 3` → `!== payload.assembly.blocks.length`.
- `tapBlock`: 잠금 `>= 3` → `>= payload.assembly.blocks.length`.
- `advanceToStep3`: 패턴 저장은 **모먼트(`recognition.isFiveHMoment && payload.pattern`)일 때만**. 아니면 저장 스킵하고 step3로.
- `complete`: `record` = {schemaVersion 6, isFiveHMoment, pattern5hId(null if !moment), triggerVerb(null if !moment), …}. `applyReview`는 **모먼트일 때만** 호출(간결형은 카드 없음). gradeFromSignals는 모먼트에서만 사용.
- `track('session_complete')` props: `pattern5hId`/`triggerVerb` nullable 허용(이벤트는 content-free라 OK), `isFiveHMoment` 추가.

## 7. 프롬프트 `prompts.ts` (최대 리스크)
`SYSTEM_PROMPT` 전면 재작성:
- 역할: "한국어 입력을 받아 **5형식이 더 나은 상황인지 판별**. 맞으면 5형식으로 재배치 + *이런 단서면 5형식*을 가르치고, 아니면 **간결형이 정답임을 인정** + *왜 5형식이 과한지/그 단서*를 가르쳐라. 목표는 강제가 아니라 *인식*."
- 새 JSON 형태(recognition, comparison reshape, pattern5h/pattern nullable, blocks 2..3) 전체 명시 + **모먼트 예시 1개 + 간결형 예시 1개**.
- `buildUserMessage` 변경 없음.

## 8. mock `mocks.ts`
- 기존 3 fixture에 `recognition:{isFiveHMoment:true}` + reshaped comparison + `pattern` 유지.
- **간결형 fixture 1개 추가**(isFiveHMoment:false, pattern5h/pattern null, betterChoice 'simpler', 2~3 blocks).
- `FIX_CAUSATIVE_BARE`('seed')는 모먼트 유지 → learn-flow e2e가 계속 5형식 워크스루.

## 9. 테스트
- `validate.test.ts`: validPayload 새 형태로 갱신 + **간결형 valid payload** 추가 + 판별 규칙별 throw 테스트(모먼트인데 pattern5h null, 비모먼트인데 pattern5h 존재, betterChoice 불일치, blocks 1개/4개 등).
- `learningStore.test.ts`: 기존(모먼트 fixture) 유지 + **간결형 경로** 테스트(패턴 저장 없음, applyReview 미호출, record.isFiveHMoment=false + pattern5hId null).
- `mocks.test.ts`: 갱신.
- `Review.tsx`: Sentences 칩이 `pattern5hId === null`이면 "간결형" 표시(크래시 방지).
- e2e `learn-flow.spec.ts`: step0 인식 배너/comparison 변경에 맞춰 셀렉터 갱신(모먼트 경로 유지). 간결형 경로는 learningStore 통합 테스트로 커버(e2e mock 선택 난이도 회피).
- 기타(srsView/progress/applyReview/db/migrate/firestore): Pattern 타입 무변경이라 영향 적음; LearningRecord nullable은 기존 테스트 팩토리가 non-null이라 통과.

## 10. 청크 계획(개요 — plan에서 상세)
1. **스키마+검증+mock+레코드+전 타입소비자 = 한 green 커밋**(타입 변경이 전 리터럴/테스트를 깨므로 원자적).
2. **스토어** (isAssemblyCorrect/tapBlock/advanceToStep3/complete 분기) + 테스트.
3. **스텝/프리미티브 UI** (StepStructure/Assemble/Feedback/Reflect, ComparisonCard, Pattern5HChip) + Review 칩 null-safe.
4. **프롬프트 재작성** + e2e 갱신 + 최종 검증.
