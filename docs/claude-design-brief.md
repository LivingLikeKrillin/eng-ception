# Eng-ception — Claude Design Brief

> 이 문서는 Claude Design에 프롬프트로 넣기 위한 컨텍스트 문서입니다.
> 앱의 정체성, 두 훈련 모드, UX 구조, 디자인 토큰을 담고 있습니다.
>
> **⚠️ 개정 (2026-06-07):** "두 훈련 모드"는 더 이상 아님 — **듣기 모드 드롭** (별도 제품 `engul`). eng-ception = 텍스트 기반 말하기 단일 모드, 웹 PWA (RN 보류, 인앱 오디오/TTS 없음). 이 브리프의 듣기 진입점·큐 카드·듣기 세션 카피 섹션은 무효 — 말하기 관련 디자인 토큰/구조만 참고.

---

## 1. 앱 정체성

**Eng-ception** — 듣고 말할 때 한국어 순서로 생각하는 습관을 깨는 도구.

한국인이 영어를 처리할 때 겪는 핵심 병목은 어휘·문법 부족이 아니라 **처리 방식**이다. 한국어 SOV 회로는 "끝까지 모아서 한 번에 처리"하는 batch processing에 최적화되어 있어서, 영어의 streaming processing(들어오는 순서대로 즉시 처리)이 자동으로 작동하지 않는다.

이 앱은 같은 병목을 **두 방향**에서 훈련한다:
- **듣기 훈련**: 영어가 들어오는 순서대로 처리하는 근육 (input streaming)
- **말하기 훈련**: 영어가 나가는 순서대로 생각하는 근육 (output streaming)

정답을 주는 앱이 아니라, 근육을 만드는 앱이다.

---

## 2. 사용자

발화 자동성이 평생 안 풀린 한국인 중상급 EFL 학습자. 어휘·문법·읽기는 충분하지만 듣기·말하기에서 지속적으로 무너진다. 이 사람들에게 "더 공부하라"는 해법이 아니다 — 처리 회로 자체를 재배선해야 한다.

## 3. 두 훈련 모드

### 3.1 말하기 훈련 (기존, 구현 완료)

한국어 문장을 입력하면 AI가 영어 발화 구조로 분해·조립하는 7-step 플로우.

```
Empathy → Pre-check → Step 0 (구조 분석) → Step 1 (블록 조립) → Step 2 (피드백) → Step 3 (패턴 저장 + 사고 전환 체크) → Step 4 (완료)
```

핵심 인터랙션: 영어 블록 3개를 순서대로 탭해서 조립 + 연결어(but, although 등) 선택. 사용자가 영어를 직접 타이핑하지 않고 **조립**한다.

### 3.2 듣기 훈련 (신규, 디자인 필요)

서버에서 큐레이션한 팟캐스트 에피소드(Hidden Brain, Radiolab 등)의 3~5분 세그먼트를 듣고 예측 훈련하는 3-phase 플로우.

**Phase 1: 스트리밍 청취 (3~5분)**
- 오디오 연속 재생, 멈춤 버튼 없음
- 안 들리는 순간 화면을 탭 → stall 마킹 (오디오는 계속 재생)
- 화면 하단에 stall 맵이 실시간으로 점으로 쌓임
- transcript 표시 없음 (텍스트를 보면 streaming이 batch로 전환됨)
- 세그먼트 끝나면 stall 요약 화면

**Phase 2: 예측 드릴 (stall 지점, 최대 5개)**
- stall 마킹된 지점 중 예측 퀴즈가 준비된 곳을 방문
- chunk 직전까지 오디오 재생 → 멈춤 → "다음에 뭐가 올까?" 선택지 3개
- 선택 후 정답 오디오 재생 + transcript 공개 + "이 구간이 안 들린 이유" 피드백
- 다시 듣기 가능

**Phase 3: 패턴 수확**
- 이 세션에서 나온 핵심 영어 구조를 패턴 카드로 표시
- 각 패턴에 한국어 다리 문장(Korean bridge) 포함
- "말하기 훈련으로" → 큐에 저장 (바로 시작하지 않음, 다음 Home 방문 시 노출)
- "지금 바로 하기" 옵션도 있음 (예외 경로)

### 3.3 듣기 → 말하기 연결 (큐 모델)

듣기에서 만난 패턴은 **바로 말하기로 넘어가지 않는다.** 큐에 저장되고, 다음번 Home 방문 시 카드로 나타난다. 이유:
- 간격 효과(spacing effect)로 장기 기억 전환율 향상
- 한 세션 부담을 10분 이내로 유지
- Home이 "할 게 있는" 상태가 되어 재방문 동기 제공

## 4. Home 화면 구조

```
Home
├── [💬 듣기에서 발견한 패턴]     ← 큐 카드 (비어있으면 숨김)
│   패턴 템플릿 + "듣기에서 만남 · 아직 말하기 안 함" + [풀어보기]
│
├── [🎧 오늘의 에피소드]          ← 듣기 진입점
│   에피소드 카드 가로 스크롤
│   각 카드: 썸네일 + 제목 + 진행도 (3/6 segments) + WPM/화자 수/토픽
│
├── [💬 바로 말하기 훈련]         ← 기존 빠른 입력 + 시나리오 카드
│   텍스트 입력 + 시나리오 카드
│
└── [최근 학습]                   ← 듣기/말하기 통합, 아이콘 구분
```

정보 우선순위:
1. 큐 카드 — 듣기에서 발견한 패턴이 있으면 최상단 (가장 높은 가치 행동)
2. 에피소드 — 새 콘텐츠 소스
3. 직접 말하기 — 항상 접근 가능, 묻히지 않게
4. 최근 학습 — 참조용

## 5. 디자인 토큰

### 색상 (다크 테마)

| 토큰 | 값 | 용도 |
|---|---|---|
| `bg` | `#111113` | 배경 |
| `c` | `#18181C` | 카드/컨테이너 배경 |
| `c2` | `#1E1E23` | 보조 컨테이너, 칩 배경 |
| `line` | `#27272C` | 테두리, 구분선 |
| `t1` | `#F2F2F5` | 주요 텍스트 |
| `t2` | `#C0C0C8` | 보조 텍스트 |
| `t3` | `#8A8A92` | 비활성 텍스트, 라벨 |
| `accent` | `#8B8BF5` | 브랜드 퍼플 (CTA, 활성 상태, 진행 바) |
| `ok` | `#5EC492` | 정답, 긍정 피드백 |
| `warn` | `#D4975A` | 오답, 주의 |

### 타이포그래피

| 용도 | 폰트 |
|---|---|
| 한국어 | Pretendard Variable |
| 영어 / 숫자 / 라벨 | Geist |

### 컴포넌트 스타일

- **카드**: `bg-c`, `rounded-[16px]`, `border border-line`, `p-[18px]`
- **CTA 버튼**: `bg-accent`, `text-white`, `rounded-[14px]`, `h-[52px]`, `shadow-[0_4px_20px_rgba(139,139,245,0.25)]`
- **비활성 버튼**: `bg-c2`, `text-t3`, `rounded-[14px]`
- **선택 버튼 (미선택)**: `bg-c`, `border-[1.5px] border-line`, `rounded-[14px]`
- **선택 버튼 (선택됨)**: `bg-accent/[0.10]`, `border-[1.5px] border-accent`
- **진행 바**: `h-[3px]`, `bg-c2` 트랙 위에 `bg-accent` 바, `bar-grow` 애니메이션
- **라벨**: `text-[11px]`, `font-en`, `tracking-wider`, `uppercase`, `text-t3`
- **피드백 카드 (정답)**: `border-ok`, `bg-ok/[0.06]`
- **피드백 카드 (오답)**: `border-warn`, `bg-warn/[0.06]`

### 모션

- 진입 애니메이션: `fu` (fade up) — 순차 딜레이 `.08s, .18s, .32s, .48s`
- 화면 전환: `sfr` (slide from right)
- 버튼 프레스: `pressable` → `pop` 애니메이션
- 진행 바: `bar-grow` (scaleX 0→1)

### 레이아웃

- 모바일 퍼스트 (390px 기준)
- 좌우 패딩: `px-6`
- 터치 영역: 최소 `py-3.5` (44px+)
- 하단 네비게이션: 탭 4개 (홈, 학습, 패턴, 복습)

### 6.2 말하기 훈련 7-step 플로우

#### Empathy (감정 공감 화면)
```
┌─────────────────────────────┐
│         (세로 중앙 정렬)      │
│                             │
│  좋은 아이디어인 건 맞는데,   │  ← text-[13px] text-t3 (echo)
│  리소스가 부족...             │
│                             │
│  아, 이거 진짜 답답하지       │  ← text-[26px] font-bold (message)
│                             │
│  같이 풀어보자               │  ← text-[15px] text-t3
│                             │
│  ───                        │  ← w-7 h-[3px] bg-accent, pulse 애니메이션
│                             │
│  PREPARING…                 │  ← payloadStatus=loading일 때만 표시
│                             │
└─────────────────────────────┘
```
- 최소 2.5초 머무름 + payload 로드 대기
- 자동 전환 (사용자 액션 없음)

#### Pre-check (방향 선택)
```
┌─────────────────────────────┐
│ ┌─ accent left border ────┐ │
│ │ 좋은 아이디어인 건 맞는데 │ │  ← OriginalCard: bg-c, rounded-[16px]
│ │ 리소스가 부족하지 않을까? │ │    border-l-[3px] border-accent
│ └─────────────────────────┘ │
│                             │
│  이걸 영어로 말한다면        │  ← text-[22px] font-bold
│  뭐부터 꺼낼 것 같아?        │  ← text-[15px] text-t2
│                             │
│ ┌──────────┐ ┌──────────┐  │
│ │ 인정부터   │ │ 걱정부터  │  │  ← 2지선다, 각 flex-1
│ │ 좋은 아이  │ │ 리소스가  │  │    미선택: bg-c border-line
│ │ 디어인 건  │ │ 부족하지  │  │    선택됨: bg-accent/10 border-accent
│ │ 맞는데…   │ │ 않을까…   │  │
│ └──────────┘ └──────────┘  │
│                             │
│  정답은 없어.                │  ← text-xs text-t3 text-center
│  지금 직감대로 골라봐.        │
└─────────────────────────────┘
```
- 선택 후 400ms 딜레이 → 자동 Step 0 전환

#### Step 0: 구조 분석 (ProgressBar 시작)
```
┌─────────────────────────────┐
│ ←  ━━●━━━━━━━━━━━━  1/5    │  ← ProgressBar: bg-c2 트랙, bg-accent 바
│                             │
│ ┌─ OriginalCard ──────────┐ │
│ │ 좋은 아이디어인 건 맞는데 │ │
│ └─────────────────────────┘ │
│                             │
│ [유형] 양보 + 주장 [업무/논리]│  ← StructureTypeChip: bg-accent/6
│                             │
│ ┌─ 이 문장이 하는 일 ──────┐ │
│ │ 좋은 아이디어인 건 맞는데  │ │  ← KoreanDecompose: role별 색상
│ │ (first=ok) (neutral=t2)  │ │    first=text-ok, pivot=text-accent
│ │ (second=warn)            │ │    second=text-warn, neutral=text-t2
│ │ ─────────────────        │ │
│ │ 핵심 구조: 인정 → 전환 → │ │
│ │ 걱정                     │ │
│ └─────────────────────────┘ │
│                             │
│  이 문장의 전환점은?          │  ← pivotQuiz
│ ┌──────────┐ ┌──────────┐  │    2지선다
│ │ 맞는데    │ │ 부족하지  │  │    정답: border-ok bg-ok/6
│ │ '좋긴 한  │ │ 않을까    │  │    오답: border-warn bg-warn/6
│ │ 데…' 하고 │ │ 걱정을 꺼 │  │
│ │ 꺾는 지점 │ │ 내는 지점 │  │
│ └──────────┘ └──────────┘  │
│                             │
│ ┌─ 피드백 (답변 후) ───────┐ │  ← bg-ok/4 border-ok/10
│ │ '맞는데'가 전환점이야.    │ │
│ └─────────────────────────┘ │
│                             │
│ [        다음 →            ] │  ← CTA, 답변 후에만 표시
└─────────────────────────────┘
```

│                             │

│ │ 좋은 아이디어인 건 맞는데 │ │
│ └─────────────────────────┘ │
│                             │
│  이제 블록을 눌러서 문장을    │
│  만들어봐                   │
│                             │

│                             │

```

#### Step 2: 피드백
```
┌─────────────────────────────┐
│ ←  ━━━━━━●━━━━━━━  3/5     │
│                             │
│ ┌─────────────────────────┐ │
│ │ 맞았어 (text-ok)         │ │  ← 정답 시 text-ok / 오답 시 text-warn

│ │ but I'm a bit concerned │ │
│ │ we might not have       │ │
│ │ enough resources.       │ │
│ │                         │ │

│ │ 잘 잡았어                │ │
│ └─────────────────────────┘ │
│                             │
│ ┌─ 설명 ─────────────────┐ │
│ │ 상대 의견을 먼저 인정하고 │ │  ← explanation
│ │ "but"으로 우려를 연결하면 │ │
│ │ 공격적이지 않으면서 명확  │ │
│ │ 하게 전달돼.             │ │
│ └─────────────────────────┘ │
│                             │
│ ┌─ WordOrderCompare ──────┐ │
│ │ 한국어                   │ │
│ │ [인정] [걱정]            │ │  ← RoleChip: ok/warn 색상

## 7. 톤 가이드

**따뜻한 반말 코치.** 느낌표 금지, 담담하고 따뜻한 톤. 점수가 아니라 진단.

| 상황 | 카피 예시 |
|---|---|
| 말하기 Empathy | "아, 이거 진짜 답답하지" |
| 말하기 정답 | "맞았어" |
| 말하기 오답 | "아쉬워. 여기는 이렇게 가는 게 맞아" |
| 듣기 세션 종료 (stall 있음) | "후반부에서 좀 흔들렸어. 같이 봐보자" |
| 듣기 세션 종료 (stall 0) | "stall 0회 — 집중해서 들었다면 좋은 신호야" |
| 듣기 예측 정답 | "맞았어. 이 흐름 잡히고 있네" |
| 듣기 예측 오답 | "아쉬워. 여기서 'overestimate'가 빠르게 지나가거든" |
| 패턴 수확 | "이 패턴 괜찮다. 나중에 말하기로 써먹어봐" |
| Home 큐 카드 | "듣기에서 만남 · 아직 말하기 안 함" |

## 7. 디자인 요청 시 참고

### 이미 구현된 화면 (말하기 훈련)
- Home (로고 + streak + hero + 빠른 입력 + 시나리오 카드 + 최근 학습)
- Empathy (중앙 정렬 메시지 + 펄스 애니메이션)
- Pre-check (원문 카드 + 2지선다 방향 선택)
- Step 0 (구조 유형 칩 + 한국어 분해 + pivot quiz)
- Step 1 (블록 3개 탭 조립 + 연결어 선택 + 프리뷰)
- Step 2 (정답/오답 배너 + 어순 비교 카드)
- Step 3 (PATTERN SAVED 카드 + Before/After 사고 전환 체크)
- Step 4 (완료 + 홈으로)

### 디자인이 필요한 화면 (듣기 훈련)
1. **Home (업데이트)** — 큐 카드 + 에피소드 섹션 통합
2. **에피소드 목록** — 에피소드 카드 그리드/리스트
3. **세그먼트 선택** — 에피소드 내 세그먼트 목록 (진행도 + 난이도)
4. **Phase 1: 스트리밍 청취** — 큰 탭 영역 + 실시간 stall 맵
5. **Phase 1 완료: stall 요약** — stall 맵 + AI 관찰 + CTA
6. **Phase 2: 예측 드릴** — 오디오 컨텍스트 + 선택지 3개 + 피드백
7. **Phase 3: 패턴 수확** — 패턴 카드 + 큐 저장/바로 하기 선택

### 디자인 방향
- 기존 v8 말하기 훈련과 **같은 디자인 언어** (같은 카드 스타일, 같은 버튼, 같은 애니메이션)
- 듣기와 말하기를 시각적으로 구분하되 통일감 유지 (예: 듣기는 🎧 아이콘, 말하기는 💬 아이콘)
- Phase 1의 큰 탭 영역은 **의도적으로 비어 보여야 함** — 사용자의 집중이 오디오에 있어야 하므로 시각적 자극 최소화
- 모든 화면 모바일 퍼스트 (390px)
